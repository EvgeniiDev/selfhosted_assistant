# Постановка задачи: миграция LLM-слоя на GitHub Copilot SDK

## Контекст
Текущий проект `selfhosted_assistant` использует собственный роутер моделей (`llm_inference/model_router.py`) и провайдеры для LM Studio/OpenRouter.

Цель этапа 1: перевести проект на архитектуру с выделенным integration layer, где основным провайдером выступает GitHub Copilot SDK.

## Что хотим получить
1. Четкое разделение слоев:
- `Application` (Telegram + бизнес-логика)
- `LLM Core` (контракты, gateway, router)
- `Integrations` (Copilot SDK, OpenRouter)
2. На этапе 1 все запросы идут через `Copilot SDK`.
3. `OpenRouter` присутствует как второй слой интеграции, но в standby.
4. Режим `text-only` (без file-edit tools и опасных shell tools).
5. Поддержка MCP tools для research/aggregation задач.

## Ограничения этапа 1
1. Без LM Studio (локальная модель не используется).
2. Без изменения бизнес-логики календаря/тасков/заметок.
3. Минимально инвазивный рефакторинг: точка внедрения через `BaseRequestHandler`.
4. Обязательное логирование выбранного провайдера, модели и fallback-причин.

## Definition of Done (этап 1, глобально)
1. Все текущие типы запросов (`calendar_event`, `task`, `note`, `unknown`) продолжают обрабатываться.
2. Основной путь генерации работает через Copilot SDK.
3. Text-only policy реально enforced.
4. MCP вызовы доступны и ограничены whitelist-правилами.
5. OpenRouter можно включить конфигом без правок application-кода.
6. Есть документы по шагам реализации, проверкам и критериям успешности.

## Не входит в этап 1
1. Возврат или поддержка LM Studio.
2. Продвинутые multi-agent сценарии Copilot CLI.
3. Автоматическое редактирование файлов агентом.

## Артефакты документации
- `01_implementation_plan.md` — дорожная карта и порядок шагов.
- `02_step_core_contracts.md` ... `07_step_rollout.md` — отдельный файл на шаг.
- В каждом шаге: действия, правила, проверки, критерии успешности.
