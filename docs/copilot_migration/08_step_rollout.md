# Шаг 7: Rollout и приемка

## Цель
Безопасно включить новую архитектуру в рабочий контур и зафиксировать критерии приемки.

## Что реализовать
1. Пошаговый rollout:
- dev/staging
- ограниченный production трафик
- полный production
2. Подготовить rollback-процедуру.
3. Обновить README с новой архитектурой и переменными окружения.

## Правила
1. Нельзя включать полный rollout без успешных тестов предыдущего шага.
2. Любой инцидент выше agreed threshold = автоматический rollback.
3. Все изменения конфигов фиксируются в changelog.

## Критерии успешности
1. На production не наблюдается деградации user-flow.
2. Ошибки по Copilot-интеграции в пределах ожидаемого уровня.
3. Rollback проверен и документирован.
4. Команда понимает, как включить OpenRouter fallback при необходимости.

## Проверка
1. Контрольные сценарии в Telegram:
- создание события
- создание задачи
- создание заметки
2. Проверка policy ограничений в production-конфиге.
3. Подтверждение актуальности README и runbook.

## Checklist приемки
1. Архитектура выделенного integration layer реализована.
2. Copilot SDK активен как основной backend.
3. OpenRouter доступен как standby.
4. Text-only + MCP whitelist работают по требованиям.
5. Документация и проверочные сценарии завершены.
