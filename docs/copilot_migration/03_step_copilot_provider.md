# Шаг 2: Интеграция Copilot SDK (активный провайдер)

## Цель
Реализовать рабочий LLM-провайдер на базе GitHub Copilot SDK как основной backend генерации.

## Что реализовать
1. Добавить `integrations/copilot_sdk/provider.py`.
2. Реализовать адаптер под `LLMProvider` контракт.
3. Поддержать:
- инициализацию клиента
- отправку prompt/messages
- возврат `LLMResponse`
- timeout/retry
- нормализованные ошибки
4. Добавить настройку auth режима:
- через локальный CLI login
- или через token env

## Правила
1. Провайдер не должен знать о Telegram update object.
2. Вся логика retry/timeout инкапсулируется внутри адаптера.
3. Ошибки возвращаются в унифицированной форме.

## Критерии успешности
1. Для тестового запроса провайдер возвращает непустой текст.
2. В ответе заполнены `provider='copilot'` и `model`.
3. При ошибке auth логируется понятная причина.

## Проверка
1. Smoke вызов провайдера отдельным скриптом.
2. Проверка негативного сценария (невалидный токен).
3. Проверка логов и структуры `LLMResponse`.

## Риски
1. Различия между версиями SDK/CLI.
2. Нестабильность preview-функций.

## Решение рисков
1. Закрепить версии зависимостей в requirements.
2. Держать OpenRouter standby для последующего fallback.
