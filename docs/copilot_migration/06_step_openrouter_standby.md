# Шаг 5: OpenRouter как standby интеграция

## Цель
Сохранить OpenRouter как второй слой интеграции, готовый к включению без изменений application-кода.

## Что реализовать
1. Добавить `integrations/openrouter/provider.py` под общий контракт.
2. Подключить провайдер в router, но держать inactive на этапе 1.
3. Добавить feature-flag для быстрого переключения active provider.

## Правила
1. Router определяет провайдер только через конфиг.
2. Обработчики и сервисы не знают о том, какой провайдер активен.
3. В standby-режиме OpenRouter не должен получать прод-трафик.

## Критерии успешности
1. OpenRouter адаптер инициализируется корректно.
2. Переключение провайдера возможно только изменением конфига.
3. Без переключения все запросы идут в Copilot.

## Проверка
1. Лог маршрутизации для нескольких запросов (должен быть `copilot`).
2. Технический тест переключения флага в dev-режиме.
3. Возврат на `copilot` без изменений в коде.

## Риски
1. Расхождения формата ответа Copilot/OpenRouter.
2. Неодинаковая обработка ошибок.

## Решение рисков
1. Строгая нормализация в `LLMResponse`.
2. Единая taxonomy ошибок внутри gateway.
